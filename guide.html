📌 1. Overview & Architecture

What is a Microservice?

A microservice is a small, independent application that does ONE job well. Instead of building one giant application that handles everything, you split the work into focused services that communicate with each other.

Simple Example:
Instead of: One giant "Food Delivery App" that handles login, restaurants, menus, orders, payments, and delivery

Do This: 7 separate microservices, each doing one job:
  • Auth Service → Only handles login/registration
  • Restaurant Service → Only manages restaurants
  • Menu Service → Only handles food items
  • Order Service → Only processes orders
  • Payment Service → Only handles payments
  • Delivery Service → Only manages deliveries
  • API Gateway → Routes requests to correct service

Why Use Microservices?

Benefit What It Means Real Example
Scalability Scale only what needs scaling During lunch rush, scale Order Service 10x without scaling Auth Service
Independence One fails, others keep working Payment Service down? Users can still browse restaurants
Team Work Teams work on different services Team A builds Auth, Team B builds Orders simultaneously
Easy Updates Update one service without redeploying all Fix bug in Menu Service, deploy only that service
Tech Flexibility Use different languages per service Auth in Spring Boot, Frontend in React, could use Python elsewhere

🔧 5. Microservices Breakdown

1. Auth Service (Port 8081)

Responsibility: User authentication, registration, JWT tokens, user profiles, addresses

Database Tables

CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    password VARCHAR(255) NOT NULL,
    name VARCHAR(255) NOT NULL,
    phone VARCHAR(15) NOT NULL,
    role VARCHAR(50) DEFAULT 'CUSTOMER',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE user_addresses (
    id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id),
    address_line VARCHAR(255) NOT NULL,
    city VARCHAR(100) NOT NULL,
    zip_code VARCHAR(10) NOT NULL,
    is_default BOOLEAN DEFAULT false
);

Key API Endpoints

Method Endpoint Purpose Auth Required
POST /api/auth/register Register new user No
POST /api/auth/login Login & get JWT No
GET /api/auth/user/{id} Get user profile Yes
PUT /api/auth/user/{id} Update profile Yes
POST /api/auth/addresses Add delivery address Yes

2. Restaurant Service (Port 8082)

Responsibility: Restaurant information, ratings, search, opening hours, cuisines

Key API Endpoints

Method Endpoint Purpose
GET /api/restaurants List all restaurants
GET /api/restaurants/{id} Get restaurant details
GET /api/restaurants/search?city=pune Search by city
POST /api/restaurants Create new restaurant (owner only)

3. Menu Service (Port 8083)

Responsibility: Food items, categories, pricing, availability, customization options

Key API Endpoints

Method Endpoint Purpose
GET /api/menu/restaurant/{id} Get all items for restaurant
GET /api/menu/item/{id} Get item details
POST /api/menu/item Add new item (owner)
PUT /api/menu/item/{id}/availability Toggle availability

4. Cart Service (Port 8084)

Responsibility: Shopping cart management, item quantities, price calculations

Key API Endpoints

Method Endpoint Purpose
GET /api/cart/{userId} Get user's cart
POST /api/cart/add Add item to cart
DELETE /api/cart/item/{cartItemId} Remove from cart
GET /api/cart/{userId}/total Get cart total

5. Order Service (Port 8085)

Responsibility: Order creation, order status tracking, order history, cancellations

6. Payment Service (Port 8086)

Responsibility: Payment processing via Razorpay, transaction records, refunds

7. Delivery Service (Port 8087)

Responsibility: Delivery partner management, order assignment, real-time tracking

6.4 Create User Model

File: model/User.java

package com.fooddelivery.auth_service.model;

import jakarta.persistence.*;
import lombok.AllArgsConstructor;
import lombok.Data;
import lombok.NoArgsConstructor;
import java.time.LocalDateTime;

@Entity
@Table(name = "users")
@Data
@NoArgsConstructor
@AllArgsConstructor
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(unique = true, nullable = false)
    private String email;

    @Column(nullable = false)
    private String password;

    @Column(nullable = false)
    private String name;

    @Column(nullable = false)
    private String phone;

    @Enumerated(EnumType.STRING)
    private Role role;

    @Column(name = "created_at")
    private LocalDateTime createdAt;

    @PrePersist
    protected void onCreate() {
        createdAt = LocalDateTime.now();
        if (role == null) role = Role.CUSTOMER;
    }
}

🐳 8. Docker Setup & Containerization

What is Docker?

Simple Explanation: Docker packages your entire application (Java, dependencies, config) into a container. Think of it like shipping your app in a box that works the same everywhere — your laptop, colleague's machine, production server.

Why Use Docker?

  • Consistency: Works the same everywhere
  • Isolation: Each service runs independently
  • Scalability: Run 100 instances with one command
  • Easy Deployment: One command deploys everything

Dockerfile Template for All Services

# Stage 1: Build
FROM maven:3.9-eclipse-temurin-21 AS builder
WORKDIR /build
COPY pom.xml .
RUN mvn dependency:go-offline
COPY src ./src
RUN mvn clean package -DskipTests

# Stage 2: Runtime
FROM eclipse-temurin:21-jre-alpine
WORKDIR /app
COPY --from=builder /build/target/*.jar app.jar
EXPOSE 8081
ENTRYPOINT ["java", "-jar", "app.jar"]

Docker Compose (Run All Services Together)

File: Backend/docker-compose.yml

version: '3.8'

services:
  postgres:
    image: postgres:15-alpine
    environment:
      POSTGRES_DB: fooddelivery
      POSTGRES_USER: admin
      POSTGRES_PASSWORD: password123
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data

  auth-service:
    build: ./auth-service
    ports:
      - "8081:8081"
    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://postgres:5432/fooddelivery_auth
      SPRING_DATASOURCE_USERNAME: admin
      SPRING_DATASOURCE_PASSWORD: password123
    depends_on:
      - postgres

  api-gateway:
    build: ./api-gateway
    ports:
      - "8080:8080"
    depends_on:
      - auth-service

volumes:
  postgres_data:

Running with Docker Compose

# Start all services
docker-compose up -d

# View logs
docker-compose logs -f

# Check status
docker-compose ps

# Stop all services
docker-compose down

🔧 11. Troubleshooting

Issue 1: "Connection refused" - PostgreSQL not running

Solution: 
# Check if running
docker ps | grep postgres

# Start it
docker-compose up postgres -d

# Or manually
docker run -d -e POSTGRES_PASSWORD=password123 \
  -p 5432:5432 postgres:15

Issue 2: "Port 8081 already in use"

Solution: 
# Find process using port
lsof -i :8081  # Mac/Linux
netstat -ano | findstr :8081  # Windows

# Kill it
kill -9 

# Or use different port
server.port=8091

Issue 3: "401 Unauthorized" on API calls

Solution:

Add JWT token to headers in Postman:

Authorization: Bearer eyJhbGciOiJIUzUxMiJ9...

Issue 4: "Maven build fails"

Solution: 
# Clear cache
mvn clean install

# Force re-download
mvn clean install -U

Issue 5: "Out of memory" error

Solution: 
# Increase Docker memory
# Docker Desktop → Settings → Resources → Memory (16GB+)

# Or reduce services
docker-compose down
docker-compose up auth-service postgres -d
